## 问题描述
**报告人**：用户
**报告时间**：2026-07-10
**问题描述**：
TermPro 终端里跑 Claude Code（Ink TUI），工具调用命令中的长路径被硬折行且续行带悬挂缩进时，路径链接只识别到折行处。

**期望行为**：
折行的长路径被识别为**一条完整链接**——整条高亮，点击打开最终目标（如 `…/apps/ios/docs/features/IOS-F001-project-scaffold`）。

**实际行为**：
只有首行末尾的前缀 `…/.worktree/IOS-F001/apps/` 成链（恰好是真实目录），续行缩进后的 `ios/docs/features/IOS-F001-project-scaffold` 完全不高亮、不可点。

---

## 复现步骤
1. TermPro 终端中让 Ink 类 TUI（如 Claude Code）输出一条含长绝对路径的命令行，路径在终端宽度处被硬折行（首行铺满到最后一列，续行另起真实新行并带前导缩进空格）；
2. 且折行点前缀（如 `…/apps/`）恰好是磁盘上真实存在的目录；
3. 观察链接高亮：仅前缀成链，缩进后的续段丢失。

**复现环境**：
- 已在 vitest + 真实 xterm buffer 中最小化复现（cols=40，行1 恰好铺满 + `\r\n` + 4 空格缩进续行；stat fake 同时含前缀目录与完整路径）：
  - `provideLinks(1)` 与 `provideLinks(2)` 均只返回 `/home/u/aif/.worktree/F1/apps/`（range 仅在行 1）——**逻辑行拼接已生效**（行 2 hover 能解析到行 1 的链接），但完整路径未成链。
- 提取层单独验证（node 直跑 `PATH_RE`）：拼接后的逻辑行文本被切出两个独立候选 `…/apps/` 与 `ios/docs/features/…`。
- 实际磁盘验证：`/Users/liam/apps/okok/aifriend/.worktree/IOS-F001/apps/`（目录 · 存在）与完整路径均真实存在——前缀 stat 命中是「只高亮半截」的直接原因。

## 根因分析（diagnose 阶段产出 · 深读代码挖真因）

### 相关代码
| 文件 | 行号 | 问题描述 |
|------|------|----------|
| `src/renderer/terminal/terminalLinkParse.ts` | 18-19 | `PATH_RE` 字符类不含空白——拼接后的逻辑行在缩进处把路径切成两个独立候选（行为本身合理，空白本就该终止路径；缺的是下游拼接） |
| `src/renderer/terminal/terminalLinks.ts` | 339-360 | `resolveCandidateSpanning` 只在**单个候选内部**做物理行对齐的前缀/后缀回退，从不尝试把「贴行尾的候选 + 下一行缩进后的候选」拼接 stat |
| `src/renderer/terminal/terminalLinks.ts` | 362-388 | `resolve()` 对候选逐个独立解析，前缀目录 stat 命中即成链，后候选 stat 落空即丢弃——两个候选间无关联逻辑 |

### 根因（真因 · 非症状）
Ink/Claude Code 硬折行时给续行加**悬挂缩进**（前导空格）。`buildLogicalLine` 的硬折行 join（首行铺满 → 拼接下一物理行）工作正常，但拼出的逻辑行文本中路径被缩进空白截断成**两个候选**：
1. 前缀 `…/apps/` 恰好是真实目录 → `fs.stat` 命中 → 单独成链（截图中下划线止于 `apps/` 的直接原因）；
2. 续段 `ios/docs/…` 作为相对路径按会话 cwd 解析 → stat 落空 → 无链接。

解析层缺少「**跨缩进缝拼接相邻候选**」的能力——这是能力缺失型根因，不是某行写错；改前缀高亮或改 PATH_RE 都是治标。

### 调用链路
```
xterm 渲染折行输出 → FsLinkProvider.provideLinks / LinkHighlighter.scan
  → buildLogicalLine(硬折行 join ✓)
  → extractCandidates(缩进处切成 2 候选 ← 断点)
  → resolve(候选独立 stat:前缀命中成半截链 · 续段落空丢弃 ← 断点)
```

## 修复方案（diagnose 阶段产出 · 🔴 用户确认后才进 dev · 本阶段不写 fix 码）

### 方案描述
**方案 A（推荐）· resolver 层跨缩进拼接**：在 `FsLinkProvider` 解析层加候选拼接尝试。触发形态：fs 候选 `c1` 结束于其物理行的行尾（其后同该行内无非空白字符），且下一物理行上存在候选 `c2`，行首到 `c2.start` 之间仅空白/gutter 字符（空格、`│`、`⎿`）。此时按最长优先先 stat `c1.text + c2.text`（可链式延伸到 3+ 行，有界）：
- 命中 → 合并为一条跨行链接（点击打开完整目标；常驻高亮只画两个候选段、跳过缩进缝），`c2` 不再单独解析；
- 落空 → 完全回退到现行为（前缀目录命中仍单独成链）。

hover 与常驻蓝色高亮共用同一 resolver，一处修复两处生效；`SystemWebLinkProvider`（web 链接）不动。

**方案 B（否决）· 提取层让 `PATH_RE` 桥接空白**：空白在终端输出中无处不在，误报爆炸；且提取层是纯文本、拿不到物理行边界，无法区分「折行缩进」与普通空格。

**取舍**：
- `fs.stat` 是最终 oracle——只有拼接后的完整路径真实存在才成链，误拼概率极低（现有「无关下一行不误拼」回归测试的安全性质保持）；
- 额外 stat 仅在「候选贴行尾 + 下一行缩进候选」形态触发，每链 O(行数) 次 RPC，且有 5s statCache 兜底；
- hover 下划线由 xterm 按 range 起止画，会覆盖中间缩进缝（与 VS Code 折行链接行为一致，视觉可接受）；常驻高亮我们自己控制分段，跳过缝隙。

## 🧩 补充洞察

- 残留风险：若某些 Ink 输出首行末列留右 padding（未铺满到最后一列），`buildLogicalLine` 的硬折行 join 不触发，本修复也不触发。回归测试已在 xterm buffer 层逐字节复刻截图形态（铺满 + 缩进续行）；「真实 Claude Code 输出铺满行尾」这一前提由 test/pm_acceptance 阶段在真实 app 里对照截图场景人工确认一次，若发现「未铺满 + 缩进续行」形态再扩 join 条件（另立回归）。
- gutter 字符集合首版取「空格 + `│` + `⎿`」；其他奇异 TUI gutter 按需追加，不预先泛化。
- **resize 后的已知限制**（External E1 · 降级为限制记录）：硬折行 join 依赖「首行铺满当前宽度」，终端 resize 变宽后历史行不 reflow、首行不再贴新右边界 → 跨行链接退化为修复前的半截前缀链（无误链，stat 兜底）。buffer 层原理上无法恢复「这曾是一条折行」；Ink 活区按新宽度重绘可自愈，仅 scrollback 中的旧输出受影响。非本 fix 引入（修复前 resize 前后都只有半截）。
- **join stat 放大观察项**（Architect A1 / External E3）：拼接落空时重叠后缀链最坏 O(链²) 次 stat。三重兜底：普通行 chain=1 零额外 stat；`statCache` 5s 同时缓存 miss（负缓存）；`MAX_JOIN_STATS_PER_LINE=12` 每逻辑行确定性预算。上线后若远程 Host `fs.stat` 出现突发负载再考虑加长负缓存。
- 既有小瑕疵（Architect A5 · 非本 fix 引入）：`rowSegments` 段尾宽字符 decoration 短 1 列 → 已记 `product-overview/PENDING.md` PENDING-007。
