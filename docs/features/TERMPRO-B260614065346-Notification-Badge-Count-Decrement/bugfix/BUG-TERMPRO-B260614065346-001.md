## 问题描述
**报告人**：用户
**报告时间**：2026-06-14
**问题描述**：
有未读通知的 tab 在被查看后，工作区顶部（侧栏左上角 🔔）通知图标上的数字角标没有跟着减少。

**期望行为**：
切到/查看一个有通知的 tab（通知视为已读）后，顶部 🔔 角标数字应同步递减；该 tab 的全部未读看完后归零。

**实际行为**：
切 tab 后 tab 的状态点 / 工作区行的 attention pill / Dock 角标都消了，但顶部 🔔 数字纹丝不动。只有去 🔔 下拉面板里逐条点击通知、或点「全部已读」/「清空」时才会变。

---

## 复现步骤
1. 启动 app，在某工作区开 ≥2 个 tab。
2. 让一个**后台**（非当前激活）tab 产生通知（命令完成 / 响铃 BEL / OSC 9·777 notify / quiet 静默判定）→ 顶部 🔔 角标 +1。
3. 点击该 tab（或用 ⌘1-9）切过去查看它。
4. ❌ 观察：tab 状态点灭了、但顶部 🔔 角标数字**没有 -1**。

**复现环境**：
- 平台：macOS（Electron）
- 范围：renderer UI，与 host / 远程无关

### 根因（真因 · 非症状）
存在**两套独立的"未读/已查看"状态，互不联动**：

- **源 A — `notifications[]`**：每条 `NotificationItem` 带 `read`，**顶部 🔔 角标只读这一套**（`Sidebar.tsx:120` `notifications.filter(!read).length`）。
- **源 B — 每 tab 的 `waiting / unseenDone`**：tab 状态点、工作区 attention pill、Dock 角标读这一套。

后台事件发生时 `sessionEvents.ts` 会**同时**写两套源（置 tab 的 `waiting/unseenDone` + `pushNotification` 推一条 `read:false`）。
但**所有"查看 tab"的路径只清源 B、从不碰源 A**：`setActiveTab`（`store.ts:253-270`，被 TabBar 点击 / ⌘1-9 / 通知点击 / 系统通知点击共用)只把目标 tab 的 `waiting/unseenDone` 置 `false`，**没有把该 tab 的 `notifications[].read` 标为 `true`**。

唯一翻 `read` 的代码只有 🔔 面板的手动操作（单条点击 `markNotificationRead` / 「全部已读」/「清空」）。因此用户切到有通知的 tab 后，源 B 清了（状态点/pill/Dock 角标都减），源 A 没动 → 顶部 🔔 数字不减。

这是**症状层（角标不减）→ 根因层（清除动作只对齐了源 B，聚合角标订阅的源 A 在 tab 查看时从不被对齐）**的关系，改症状（例如让角标改读源 B）会引出新的 drift；正解是在"查看 tab"这一收口把源 A 一并标已读。

### 调用链路
```
用户点 tab / ⌘1-9 / 点通知条
  → setActiveTab(workspaceId, tabId)        [store.ts:253]
      → 仅 tabs.map: waiting=false, unseenDone=false   (源 B 清)
      ✗ notifications 未触碰                            (源 A 残留 read=false)
  → Sidebar unreadCount = notifications.filter(!read).length  [Sidebar.tsx:120]
      → 不变 → 顶部 🔔 角标数字不减
```

## 修复方案（diagnose 阶段产出 · 🔴 用户确认后才进 dev · 本阶段不写 fix 码）

### 方案描述
**在 `setActiveTab`（`store.ts:253-270`）这一"查看 tab"统一收口，激活时把该 tab 的未读通知一并标为已读**，使源 A 与源 B 在查看时对齐。在 `set((s) => ...)` 的返回里，除现有 tab `waiting/unseenDone` 清零外，新增：

```ts
notifications: s.notifications.map((n) =>
  n.tabId === tabId && !n.read ? { ...n, read: true } : n,
),
```

为什么是这一处：`setActiveTab` 是**所有主动查看某 tab 的唯一收口** —— TabBar 点击（`TabBar.tsx:95`）、⌘1-9（`App.tsx`）、🔔 面板点通知条（`NotificationCenter.tsx:67`）、系统通知点击（`sessionEvents.ts`）全部经过它。改一处即覆盖全部激活路径，角标随之递减。

- `clearTabAttention` **无需改**：它唯一的调用方 `NotificationCenter.handleItemClick`（`:68`）在调它之前已先调 `setActiveTab`（`:67`），新增逻辑已覆盖。
- 窗口 `focus` 回看（`sessionEvents.ts` 的 `clearAttention`）**不改**（建议）：仅切回 app 未必看了那个 tab，标已读过激进。
