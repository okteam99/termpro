## §4 🔴 三项待你裁决的事(一次性列出,不分散打扰)

### ① R5 · 远端部署锁「未实测」

**是什么**:在 `deploying` 阶段点取消,可能在远端留下一把部署锁,导致**下一次连接最长空等 120 秒后失败**(再点一次即恢复,不是死锁)。

**做到哪一步**:机理已**逐行代码读证**并记入 `KNOWLEDGE.md GO-037`(`deploy.ts:37/118/213` + `orchestrator.ts:419` + `mkdirLock.ts:88-92`)。**没有实测**。

**为什么没实测**:实测要真连一台远程机、在部署中途取消 —— 那会**在你的远端留一把真锁**,让你下次连接卡满 120 秒。这是对你真实基础设施的副作用,不该由我自决。

**选项**:现在补实测(我需要你指定用哪台机)/ 接受读证结论不实测 / 记入 PENDING 后续再说。

### ② 拆除语义两套(既存问题 · 非本次引入)

**是什么**:从**设置页**断开时,不走 `stopRemoteWorkspaceSync` —— 该机的项目会**留在侧栏**、激活项目**不会回落本机**。也就是说 **AC-12 只在侧栏入口成立**。更麻烦的是 `forWorkspace` 对缺失的远程 client 会兜底返回本机,残留的项目若被消费会**静默路由到本机**。

**范围判定**:这是**既有行为**,本 Feature 没引入也没修(PRD 范围是侧栏控件;本次只把设置页的**弃用语义**收敛到 store 单源)。

**改动成本**:一行(把设置页那句 `hostRegistry.drop(id)` 换成 `stopRemoteWorkspaceSync(id)`),**但会改变用户可见行为** —— 从设置页断开后该机项目会消失。所以不由 dev 自决。

**选项**:本次顺手修 / 单独立项 / 维持现状。

### ③ 握手编排两份(TECH 从 blueprint 就记着的 TODO)

**是什么**:侧栏和设置页**各有一份** `beginHandshake` 实现。TECH §简洁性自查 早就写过一句话:「重复实现意味着每个新增的不变式都要记得在两个地方各写一遍」。

**本 Feature 期间它应验了两次**:一次是设置页那份握手漏设闸(dev 期发现,已补);一次是三个只差 label 的连接钮分支(review F10,已收敛成一个)。

**选项**:单独立项收敛 / 维持现状(每次改动记得两处都改)。
