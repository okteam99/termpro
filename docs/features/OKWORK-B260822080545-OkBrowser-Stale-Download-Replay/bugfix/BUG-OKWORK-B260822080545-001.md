# Bug 排查报告：OkBrowser 重放历史下载标签

## 状态

🔧 已按确认方案完成实现与定向回归；完整门禁结果由 dev 状态机证据记录。

---

## 问题描述

**报告人**：用户

**报告时间**：2026-08-22

**问题描述**：点击任意新链接打开 OkBrowser 时，macOS 反复弹出旧文件 `vbclient-so-1.1.4.zip` 的 Save As 对话框；当前可见浏览器标签实际是新的 GitHub 链接。

**期望行为**：打开新链接只加载用户刚点击的当前标签；后台历史浏览器标签不应在未被用户激活时自动发起网络请求或下载。

**实际行为**：BrowserPanel 从隐藏状态挂载后，同时创建所有 workspace、所有终端会话的历史 webview；一个不可见的后台 ZIP 标签因此重新触发下载。

---

## 复现步骤

1. 在某远程终端的 OkBrowser 中打开直接 ZIP URL，并保留该浏览器标签。
2. 隐藏/关闭 BrowserPanel，使组件卸载；历史浏览器标签仍由 store 持久化。
3. 切换到另一个 workspace/终端，点击任意安全链接，例如 GitHub PR。
4. 新链接先成为当前可见标签，BrowserPanel 随后挂载。
5. 观察：安全链接正常显示，但后台历史 ZIP webview 同时创建并触发旧文件 Save As。

**复现环境与实证**：

- 发布版本：OkWork `v0.3.117`
- 本机持久化状态中发现两个完全相同的 ZIP 标签（报告已脱敏真实主机地址）：
  - Host：远程 Host（身份已验证，标识不入库）
  - workspace cwd：`/workspace/matrixpower`
  - 后台终端：三条终端中的第二条
  - 浏览器标签索引：8、9；URL 路径均以 `/solib/vbclient-so-1.1.4.zip` 结尾
- HTTP HEAD：`200 OK`、`Content-Type: application/zip`、`Content-Length: 7,229,266`
- 临时 BrowserPanel 反馈环：安全 GitHub 标签为当前标签、后台终端保留 ZIP 标签；连续 3/3 次都在 DOM 中创建 ZIP webview，单次约 0.7 秒。临时测试已删除。

## 根因分析

### 相关代码

| 文件 | 行号 | 问题描述 |
|---|---:|---|
| `src/renderer/App.tsx` | 284–290 | `browserPanelOpen` 从 false→true 时重新挂载整个 BrowserPanel |
| `src/renderer/components/BrowserPanel.tsx` | 664–691 | 当前可见 workspace、终端与浏览器标签已明确可计算 |
| `src/renderer/components/BrowserPanel.tsx` | 1247–1297 | 渲染时却遍历所有 workspace/终端/浏览器标签并创建全部 webview，不区分本次面板会话是否访问过 |
| `src/renderer/state/persistence.ts` | 251–267 | 普通浏览器标签 URL 会持久化；直接 ZIP URL 与普通网页 URL 没有生命周期区别 |
| `src/renderer/services/openBuiltinBrowser.ts` | 36–40 | 点击新终端链接会先追加并激活新标签、再打开面板；新 URL 本身没有被改写 |

### 根因

“保活”需求被实现成了“每次 BrowserPanel 挂载时立即复活所有历史标签”。这混淆了两个生命周期：

- **本次面板会话内已经访问过的 webview**：应继续挂载，避免切换 workspace/terminal/browser tab 时页面重载。
- **仅从磁盘恢复、用户本次尚未访问的后台标签**：不应在面板打开瞬间发起请求。

历史直接下载 URL 被当普通网页持久化后，eager mount 让它在后台重新请求。由于响应是 `application/zip`，Electron/Chromium 启动原生下载流程；Save As 覆盖在当前可见的新标签之上，形成“任意链接都触发上一次下载”的表象。

### 调用链路

```text
终端安全链接
  → openTerminalLinkViaPolicy
  → openBuiltinBrowser
  → addBrowserTab（安全链接成为 active）
  → browserPanelOpen=true
  → App 挂载 BrowserPanel
  → BrowserPanel flatMap 所有 workspace/terminal/browser tabs
  → 创建后台 matrixpower ZIP webview
  → HTTP 200 application/zip
  → Electron/Chromium Save As
```

### 其他假设核验

- **FilePanel/查看器旧保存框仍 pending**：不是主因。真实状态中存在两个精确 ZIP 浏览器标签，组件反馈环无需 FilePanel bridge 即可复现后台挂载。
- **新链接被路由器改写成旧 URL**：排除。`openBuiltinBrowser` 将新 URL 追加为独立 UUID 标签；复现中安全链接与旧 ZIP 是两个并存 webview。
- **`target=_blank` 弹窗重放旧 URL**：排除为主因。终端普通链接不经过该分支仍能稳定复现。
- **自动下载到 Downloads 可解决**：拒绝。它只隐藏 Save As，不阻止历史请求；已完成下载下次仍会再次下载，并且未经用户确认改变下载落点语义。

## 修复方案

### 推荐方案：lazy mount + panel-session keep-alive

在 `BrowserPanel` 内维护仅存在于组件生命周期的 `mountedBrowserTabIds`：

1. 当前可见的浏览器标签始终立即渲染，不等待 effect。
2. `activeTabId` 每次变化后加入 `mountedBrowserTabIds`；之后切到其它标签/workspace/terminal 时，该 webview 在本次 BrowserPanel 挂载期间继续存在。
3. 渲染全局 browser tabs 时，仅创建“当前 active”或已进入 keep-alive 集合的标签；磁盘恢复但本次未访问的后台标签不创建 webview。
4. workspace/tab 被删除时同步裁剪 keep-alive 集合，避免内存集合增长。
5. BrowserPanel 隐藏后组件卸载，keep-alive 集合自然清空；下次打开只从新的当前标签开始。

### 保留的不变式

- 当前标签首帧立即出现。
- 本次面板会话内访问过的标签跨 browser/terminal/workspace 切换继续保活，不 reparent、不 reload。
- 普通浏览器标签继续持久化；不引入 URL 扩展名启发式。
- 下载仍由 Electron/Chromium 按现有行为处理，不自动改保存目录。
- Profile × 出口分区、Remote Profile hydration gate、弹出窗格语义不变。

### 回归测试计划

在 `BrowserPanel.test.tsx` 使用真实 store 和真实 BrowserPanel 渲染入口覆盖：

1. 当前安全链接 + 未访问的后台 ZIP 标签 → 只挂安全标签，不挂 ZIP。
2. 切换到后台终端/标签 → ZIP 标签此时才挂载。
3. 再切回安全标签 → 已访问的 ZIP webview 仍保活，证明不是简单“只渲染 active”。
4. 删除/关闭标签后 keep-alive 集合收敛，不残留 webview/ref。
5. 既有 window.open 来源落位、Remote Profile hydration 和窗格弹出测试保持通过。

### 备选方案与取舍

- **过滤 `.zip/.dmg/...` URL 持久化**：实现简单但启发式不可靠；无扩展名的附件漏掉，可在线预览的二进制又会误删。
- **main `will-download` 后自动保存/去重**：改变用户下载语义，且只治弹框不治后台请求。
- **只渲染当前 active 标签**：会破坏现有保活目标，用户一切换标签就重载页面；不采用。

## 🧩 补充洞察

“保活集合”必须表达“本次 UI 生命周期中用户实际触达过”，而不能直接等同于“持久化数据中存在”。磁盘恢复负责可达性，运行时挂载负责副作用；二者混成一个集合就会把恢复动作变成后台执行动作。
